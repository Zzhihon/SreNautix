# 0121 阶段 B 的假设根因使用组件粒度

## 背景

阶段 A 的归并与根因候选都用组件粒度：`TopologyGraph.componentOf` 沿 owned_by 向上取顶层属主，Pod 归到 Deployment、StatefulSet 或 CNPG Cluster。阶段 B 的假设账本直接使用模型给出的组件键，模型常把根因写成具体的 Pod（例如某个 CNPG 实例 Pod 或某个 worker Pod），于是：

- 同一个工作负载的 Pod 与属主成为两个竞争假设，两者都处于支持状态时互相打平；
- 假设的范围只包含根因直接拥有的对象，Deployment 的 Pod 经 ReplicaSet 拥有，Pod 上的异常卡支持不了 Deployment；
- Pod 在发布与重启后被替换，以 Pod 为根因的结论无法作为处置对象，也与按组件标注的评测答案不一致。

CCHP 重建评测中，大模型路由有 6 次运行的结论停留在 Pod，标注的根因是它的属主。

## 决定

1. **根因改写为顶层属主**：账本合并模型给出的假设时，沿研判子图中的 owned_by 边向上取顶层属主作为假设的根因（与阶段 A 的 `componentOf` 规则相同）；子图中没有属主的对象（节点、外部依赖、领域包组件等）不变。改写写入 `validation_notes`。
2. **合并落在同一组件上的假设**：改写后与另一个假设的根因相同时，并入那个假设，支持与反驳引用合并；被并入的 id 记为别名，模型之后在检查、结论、修复建议与提议中引用它时按别名改写到保留的假设。模型下一轮把这个 id 用于别的组件时别名解除。
3. **范围沿 owned_by 向下传递**：假设的范围是根因本身、根因直接依赖的对象（置信度不低于 τ），以及沿 owned_by 向下的全部成员（Deployment → ReplicaSet → Pod）。成员自身的依赖（例如 Pod 所在的节点）不进入属主的范围，节点上的异常需要以节点为根因的假设来解释。
4. **反馈按同一粒度比对**：人工反馈与上一次结论中的根因先取顶层属主再与账本比对。
5. **提示词**：hypothesize 说明根因按组件粒度填写，由控制器拥有的对象写顶层属主。

## 结果

- 实现在 `apps/srenautix/src/research/ledger.ts`（`ownerOf`、`scopeOf`、`Ledger.resolve`、`Ledger.componentOf`），控制器与代码校验按别名改写引用；契约不变。
- 单元测试覆盖属主链、传递范围、合并与别名、别名解除、反馈比对。
- 以 Pod 为粒度的处置动作（例如重启某个 Pod）仍可在提议中使用：提议的目标只要求在研判子图中，与结论根因的粒度无关。

# 0070 `@srenautix/ui`：共享组件与注入的数据端口

## 背景

控制台与 Grafana 插件都要显示收件箱、事件详情、研判运行明细与审批信息（DESIGN §12.5）。两处的外壳不同：控制台有自己的路由、会话与主题，插件运行在 Grafana 里，沿用 Grafana 的主题、语言、用户与 URL。界面约定（状态用图标加文字、空状态写明原因、模型生成的内容单独标注、不可信原文只作为文本）必须在两处一致。

## 决定

1. **两层组件**：原语（状态标签、按钮、面板、空状态、标签页、抽屉、悬停提示、表格、图表、表单）与领域组件（VerdictHeader、EvidenceCard、HypothesisList、TimelineLane、IncidentRow、ApprovalSheet、RunTrace、ConditionStrip、根因子图）。在此之上有四个共享视图：收件箱、事件详情、研判运行明细、审批页。视图只接收数据端口、链接与能力，不依赖任何宿主的路由。
2. **数据端口 `DataPort`**：方法与 `contract/openapi.yaml` 的 operationId 一一对应，类型取自契约生成的 OpenAPI 类型。写操作（审批、拒绝、撤销、重新研判、实时重跑）放在可选的 `actions` 中；反馈是唯一不在 `actions` 中的写操作，因为插件也允许反馈。一份基于 openapi-fetch 的 HTTP 实现由两个宿主共用，区别只在根地址：控制台访问同源的 `/v1`，插件访问插件后端的资源路径。浏览器端只引用契约的类型，不打包 JSON Schema 与 Ajv。
3. **宿主环境 `UiEnv`**：数据端口、页面链接（`approvalExternal` 表示审批在宿主之外打开）、能力（反馈、重跑、审批与只读说明）、宿主的链接组件。审批页在插件里只给出打开控制台审批页的链接。
4. **设计令牌**：组件的样式只引用 `var(--sn-*)`。控制台用自带的浅色与深色两套；插件用 `tokensFromGrafana(GrafanaTheme2)` 映射出来的一套（`@srenautix/ui/grafana` 入口，组件本身不依赖 `@grafana/*`）。弹层挂在令牌作用域内的容器上，所以弹层同样带着令牌。
5. **文案**：ICU MessageFormat，zh-CN 为默认、en 为第二语言，包导出 `messages/<语言>.json` 供服务端渲染共用。缺少的键直接报错；测试检查两种语言的键集合相同、每个状态枚举都有文案、每条文案都能解析。
6. **状态**：每个领域枚举（证据判定、处置判断、结论阶梯、严重度、事件、假设、区分性检查、提议、执行、研判、反馈、条件）在一张表里给出语气与图标，标签总是图标加文字，颜色只是辅助；"无法判定"与"能力缺失"用虚线边框，与"正常"区分。
7. **证据的两份结果**：EvidenceCard 默认显示研判当时的快照，并标注"模型所见"；实时重跑的结果放在旁边，标注"非模型所见"，判定发生变化时单独提示。卡片中的表格、时间线里标为 untrusted 的原文放进注明来源的引用样式，只作为文本渲染。

## 结果

- 插件与控制台的同一个页面行为一致；插件只多一层主题映射与链接改写。
- 组件测试在真实 Chromium（vitest 浏览器模式）中运行，uPlot、ResizeObserver、Radix 的焦点管理按真实行为执行；样例数据在测试里先经契约 JSON Schema 校验。
- 契约字段变化时，类型检查直接指出受影响的组件。

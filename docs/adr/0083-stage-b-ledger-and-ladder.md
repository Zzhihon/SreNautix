# 0083 阶段 B：代码维护的假设账本、区分性检查与结论阶梯

## 背景

DESIGN §7.2–§7.4 要求阶段 B 分 hypothesize、discriminate、conclude 三步；假设账本由代码维护，模型不直接调用工具；`evidence_consistent` 只能由代码判定；结论经代码校验；证据指纹不变时不调用模型；指纹变化时从上一份账本增量研判；反馈作为输入。

## 决定

1. **运行内证据编号**：阶段 A 的证据卡保持原编号 `card:<n>`，区分性检查产生的卡接着编号；成员告警为 `alert:<n>`，变更为 `change:<n>`。编号到卡片定义与实体的映射写入研判清单的 `evidence_map`。动态枚举 `evidence_refs` 只含本次运行存在的编号。
2. **账本状态由代码判定**（模型只输出假设、机制与引用）：
   - 假设的范围是根因组件本身、它直接依赖的对象（边从根因出发、置信度不低于 τ=0.6，例如挂载的 PVC、所在节点）与它拥有的对象（`owned_by` 指向根因，例如 Deployment 的 Pod）；调用根因的上游只会表现出症状，不在范围内；
   - **支持**：范围内有异常卡（模型引用的、针对它的检查产生的，或实体就是根因组件本身的阶段 A 卡）；
   - **推翻**：针对它的检查结果为正常；或没有支持卡，而它的机制信号上有相反的正常卡（与支持卡同一卡定义的范围内正常卡、模型引用为反驳的范围内正常卡、根因组件自身的阶段 A 卡全部正常且有数据）；
   - **检验后仍无法判定**：执行过检查但既没有支持也没有推翻；
   - 人工反馈固定的状态（确认为支持、否定为推翻）不再被证据改变；只采用已绑定账号的反馈，以最新一条为准。父子关系必须是树，构成环的父引用断开并记录。
3. **区分性检查由控制器执行**：每轮取排名前 N（默认 3）个未固定、未推翻、尚未检验的假设，各执行模型给出的一项检查。`type: query` 是领域包的查询模板，结果按模板附带的卡定义用 CEL 判定（判定方式 rule）；`type: tool` 是只读工具（内置或 MCP 白名单工具），结果由小模型对照 `refutes_if` 判定成卡（判定方式 model，契约 `reason.kind = model_judged`）。type 与目标所在列表不符时改正，参数文本按修复阶梯的 jsonrepair 一级修复，修改都写入 `validation_notes`。参数不合格、数据源报错或结果无法判定成卡的检查记为失败，不算"检验过"。
4. **停止规则**（满足任一即进入 conclude）：排名第一的假设得到支持，且其余假设都已推翻或检验后仍无法判定；连续两轮账本状态没有变化，或没有可执行的新检查；达到轮数上限（默认 3）；剩余时间不足 conclude 的预留（默认 2 分钟）；预算截停。每轮之间带着账本重新执行 hypothesize。
5. **结论阶梯**：`evidence_consistent` 必须同时满足四项（契约 `ConsistencyChecks` 逐项记录）：范围内有由领域包规则判定的支持卡；其中至少一张的异常起始时间不晚于最早的症状告警加 2 分钟；范围内没有相反的正常卡；至少检验过一个竞争假设。只有模型判定的支持卡时最多是 `likely`。有支持但不满足全部条件为 `likely`；有假设没有支持为 `inconclusive`；没有假设为 `undetermined`。
6. **代码校验**：结论选中的假设必须在账本中且未被推翻；提议必须在本集群可用的动作中、参数符合动作 schema、目标是本次研判拓扑中的组件（机器推导的目标）、依据的假设未被推翻；修复建议按 mitigation → root_fix → prevention → investigation 排序、每类最多 3 条，runbook 与动作不在列表中时置空，引用清理；观测失明时处置一律为 escalate；处置为 act 但没有有效提议或规则提议、或根因无法判定时，critical 改为 escalate，其余改为 undetermined。所有修改写入 `validation_notes`。
7. **指纹门控与增量研判**：证据指纹与上一次完成的研判相同、且之后没有新的已绑定反馈时，不调用模型，沿用上一次的输出并追加"仍然一致"。指纹变化时把上一份账本作为起点（假设与状态保留，根因组件改变的假设重新检验），提示词中附上上一份账本与反馈。
8. **期限**：阶段 B 的硬期限默认 8 分钟，同时不晚于 server 下发的 `deadline_at`；单次调用超时见 ADR 0080。

## 结果

- 账本、停止与阶梯的每一个判定都能在运行明细中找到依据；`srenautix_research_conclusions_total` 按档位、是否仍有未检验竞争假设、是否零检查计数，P0 指标 `srenautix_research_untested_competitor_ratio` 与诊断指标 `srenautix_research_zero_tool_ratio` 按最近 7 天计算。
- 在本地 Qwen3 1.7B 上录制的完整研判（`test/fixtures/llm/research/pvc-full.json`）覆盖了父子环、type 写错、工具参数缺字段、参数多一层转义、编造的查询语法、结论超出输出上限后重新请求、修复建议 id 不合格式、提议目标为占位符等真实的小模型输出问题，回放测试逐项断言处理结果。场景评测中，去掉根因异常卡的反事实用例三次都正确地弃权：调用根因的上游的症状卡不在假设范围内，不能证明根因。

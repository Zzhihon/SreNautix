# 0202 故障域提前熔断前先发一次探测调用

状态：已采纳

本 ADR 修改 [0080](0080-model-layer.md) 的故障域提前熔断与 [0152](0152-last-resort-model-route.md) 决定第 2 条。

## 背景

ADR 0080 的故障域提前熔断只看事件的组件：事件涉及某条路由 `failure_domain` 里的组件，这条路由就对本次研判视为打开，不发任何请求。ADR 0152 在全部常规路由都这样打开时改用兜底路由。

CCHP 的部署里，常规路由都经过 CCHP 自己的模型网关，`failure_domain` 写的是网关的组件（`component:gateway`、`StatefulSet:cchp-prod/gateway` 与各个 Pod）。2026-11-05 到 11-12 的线上状态库：

- 484 次研判中 129 次以 `model_unavailable` 失败；
- 其中 11-11 之后有 36 次是"常规路由全部因故障域提前熔断，兜底路由返回 402（账户余额不足）"，最终 0 token、只出阶段 A；
- 这些事件大多是网关的单个 Pod 被驱逐、重启或延迟升高，网关整体仍在服务。事件涉及网关组件不等于网关不可用。

只看事件组件的判断把"网关上有事件"当成了"网关不可用"。网关的大部分事件里常规路由其实可用，研判却被跳过，或者被送到费用更高、数据流向不同的兜底路由。

## 决定

1. **先探测，后熔断**：会话确定路由组时，对事件涉及其故障域的每条常规路由发一次探测调用。探测成功，这条路由照常参与本次会话；探测失败，这条路由才对本次会话提前熔断。没有涉及故障域的路由不探测。
2. **探测调用**（`DOMAIN_PROBE`）：
   - 只含固定文本 `Reply with the single word: ok`，不含事件数据，输出上限 16 token，流式发出；
   - 超时：首 token 20 秒、空闲 10 秒、合计 30 秒，比研判调用短。网关不可用时探测在 30 秒内给出结论；
   - 与研判调用走同一个客户端、同一套出站检查、计量与熔断器。探测失败按 `LlmError.countsAsFailure` 计入熔断器，与真实调用失败相同；
   - 2026-11-13 在 CCHP 网关上实测：`claude-fable-5-2`（Messages）3.9 秒、`gemini-4-carbon` 12.2 秒、`glm-5.3` 2.8 秒。
3. **按路由缓存**：探测结论在模型层按路由缓存 60 秒；进行中的探测由同时到达的会话共用，一次网关事件引起的多个并发研判只发一次探测。探测本身抛出意外错误时不缓存。发起探测的会话把探测的 token 与成本记到自己的研判上，并在出境清单里记一条（数据类别为空）；探测不写调用记录。
4. **兜底路由不探测**：兜底路由涉及事件的故障域时照旧直接提前熔断（ADR 0152）。兜底路由只在全部常规路由都经探测失败而提前熔断时成为路由组。这条修改 ADR 0152 决定第 2 条的条件；决定第 3 条不变：研判中的真实调用失败照旧只在常规路由之间切换。
5. **路由组在第一次调用前确定**：`ModelSession.plan()` 是异步的，可以重复调用、只执行一次。阶段 B 在指纹门控之后、组装提示词之前调用它（提示词按路由组中最小的上下文组装）；指纹门控沿用上次结论时不探测。`structured()` 自己也会调用。
6. **记录**：
   - 尝试记录与失败说明写明探测失败的原因：`<路由>：事件涉及该路由的故障域组件 <组件>，探测调用失败（<原因>），提前熔断`；
   - 指标 `srenautix_llm_failure_domain_probes_total{route, outcome}`，`outcome` 为 `ok` 或 `failed`，缓存命中不计；`srenautix_llm_failure_domain_skips_total` 只在探测失败后计数。

## 考虑过的方案

- **删除故障域提前熔断，只靠真实调用失败**：最简单。代价是网关真的不可用时，每个研判都要等一次研判调用超时（首 token 上限按模型类别是 60–120 秒）才切路由，阶段 B 的期限被这段等待占掉；兜底路由也就无从触发（ADR 0152 决定第 3 条）。
- **用网关自己的健康检查代替探测**：不消耗 token。代价是健康检查只说明网关进程在线，不说明上游模型可用；并且要求 worker 能访问网关的内部端点，这与路由只配置一个 `base_url` 的约束不符。
- **探测结论缓存更久（例如 5 分钟）**：探测次数更少。代价是网关在缓存期内恢复或失效时，结论滞后；60 秒内一次网关事件引起的并发研判已经共用一次探测，更长的缓存节省有限。

## 结果

- 事件涉及网关组件、但网关仍在服务时，研判照常使用常规路由；
- 网关真的不可用时，每条常规路由最多 30 秒得到探测结论，之后与原来一样改用兜底路由或只出阶段 A；
- 每次涉及故障域的研判多一次约 50 token 的调用（同一路由 60 秒内共用）。

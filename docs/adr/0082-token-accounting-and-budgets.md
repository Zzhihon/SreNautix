# 0082 token 计量与预算

## 背景

DESIGN §7.5 与 §8.3 要求按服务方返回的 usage 计量，发送前的估算按路由持续校准，按阶段与按天设置预算：每天达到 80% 时 warning 及以下事件只出阶段 A，达到 100% 时只有 critical 进入阶段 B；回放与评测在当日预算用尽时推迟。

## 决定

1. **计量**：每次调用记录服务方 usage 中的输入、缓存命中的输入、输出与推理 token，按路由单价（缓存命中部分按缓存单价）计算成本。
2. **估算与校准**：发送前对实际请求体估算输入 token。方言档案声明了 tiktoken 分词器时按分词器数；其余按每 token 至多 2 字节保守估算。每次调用后用"实际输入 ÷ 原始估算"更新该路由的校准系数（指数加权平均，同时保留缓慢回落的最近最大值），之后的估算取二者较大者再加 10% 余量。校准系数保存在 `worker.route_state`，并导出为 `srenautix_llm_estimate_calibration`。
3. **单次与单次研判的上限**：每个阶段有单次调用的输入与输出上限（输出上限直接作为 `max_output_tokens`），每次研判有输入合计上限（默认 150k）。估算超过上限时这次调用不发出，研判以 `budget` 结束；估算加输出上限超过路由的上下文长度时换下一条路由。
4. **每日预算**：`worker.daily_usage` 按 UTC 日累计全部模型调用的 token（输入 + 输出）。worker 认领任务后先检查：达到 `daily_warn_ratio`（默认 0.8）时非 critical 事件只出阶段 A；达到上限时按 `on_exhausted` 只放行 critical（默认）或全部只出阶段 A。每次研判结束后把当日比例上报给 server（`POST /v1/research/budget`），server 在入队时做同样的截停；比例导出为 `srenautix_llm_budget_used_ratio{scope="daily"}`。
5. **评测**：`srenautix eval` 有自己的 `--max-tokens` 上限，达到后不再开始新的运行并在报告中写明跳过的次数。部署方可以把评测与研判放在同一个每日预算下（worker 的用量表），也可以让评测在预算推迟到次日的时段运行。
6. **稳定前缀**：提示词按"固定指令 → 目录（查询模板、只读工具、动作、runbook）→ 事件数据 → 步骤相关部分 → 任务说明"排列，hypothesize 与 conclude 共用前三段，便于服务方的前缀缓存命中。

## 结果

- 没有公开分词器的模型也能在第一次调用后得到接近实际的估算；估算偏差持续可见。
- 每日上限是配置项（`budget.daily_tokens`），没有内置默认值，部署方必须明确写出。

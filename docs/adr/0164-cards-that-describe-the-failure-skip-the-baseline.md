# 0164 描述故障类型的卡不取证据基线

## 背景

证据基线（ADR 0153）把判为异常的卡放到事件之前的时段重新判定，多数时段同样异常、或主值在过去的波动范围内时判为常态：常态的卡不算支持证据，模型引用为支持时代码删除这条引用。这对检测类的卡是对的：一直在报错的上游、每个工作日都会顶到上限的 HPA，在事件窗口里同样成立，不能说明这次的原因。

一组外部上游的事件里，部署方的领域包增加了三张区分机制的卡：同期其他上游是否正常、失败是否集中在一个模型、失败是什么类型（限流冷却、认证失败、连接失败与超时、上游错误响应）。重建评测中，这三张卡在当下的结论是对的，却都被判为常态：

- 一个上游的额度已经用尽了几天，"限流冷却占失败的一半以上、最近 24 小时限流 4.8 小时"在过去每个时段都成立；
- 一个图片模型的供给在前几天也多次失败，"失败集中在这个模型、它在其他上游上同样失败"在过去也出现过。

账本删掉这些支持之后，模型把机制写成"既有错误的时间分布让告警条件首次连续满足"或"告警计数与分母异常"，没有写出额度用尽和模型供给。这三张卡回答的是"这次是什么类型的故障"，同一类型的故障过去出现过，不说明这次不是这个类型。

## 决定

证据卡增加 `baseline`（布尔，默认 `true`，契约 2.35.0）。`false` 时：

- 阶段 A、区分性检查的卡片检查与查询模板的卡（同一个执行器，`PackEvidence.execute`）判为异常时不取基线样本，结果没有 `novelty`；
- 没有 `novelty` 的异常卡在账本、提示词、处置与修复模板里的处理与 ADR 0153 之前相同：照常作为支持证据。

适用于描述故障类型的卡：失败按错误类型、按模型或按其他维度的分布，与同类对象的同期对照（其他上游、其他副本）。检测某个条件是否出现的卡（错误率、延迟、重启、容量、告警条件卡）保持默认，继续取基线。`docs/packs/README.zh-CN.md` 写明这条约定。

## 影响

- 契约 2.35.0：`contract/schemas/evidence-card.schema.json` 的 `baseline`；旧版本的 server 加载声明了这个字段的包会因为 schema 校验失败而拒绝这个包，包需要在 server 升级之后再声明。
- 测试：`test/integration/stage-a-novelty.test.ts` 在真实 Prometheus 上用同一组长期重启的数据对照：普通的重启卡判为常态，声明 `baseline: false` 的卡判为异常、没有 `novelty`（夹具包 `test/fixtures/packs-baseline/baseline-off`）。

# 0149 长期事件的卡片窗口以评估时刻为终点

## 背景

真实事件（Zzhihon/SreNautix#13 第 3 项）：CCHP 上 7 个 PodDisruptionBudget 事件的 first_firing_at 在 10-11，`kube_poddisruptionbudget_*` 指标 10-13 才开始有数据。

卡片窗口以首次触发为锚点（ADR 0107 §7、ADR 0131），取 [锚点 − before, min(锚点 + after, 评估时刻)]。窗口落在指标出现之前两天，PDB 的卡全部没有样本，判为无法判定。半数以上的卡无法判定时，处置就是 escalate（observability_blind），于是开出了 cchp-k8s-ops #260、#261。

事件仍在触发，问题出在窗口：卡片看的是两周前的一小段，而不是现在的状态。只有成员告警晚于窗口开始时，才按那条告警重新锚定（ADR 0107 §7）。长期存在、没有新告警的事件，窗口一直停在首次触发。

## 决定

1. **终点取评估时刻**：评估时刻是研判时刻，事件已恢复时取恢复时刻（不晚于研判时刻）。它晚于锚定窗口的终点（锚点 + after）时，卡片窗口终点改为评估时刻。
2. **起点**：取 max(锚点 − before, 终点 − 最大窗口, 评估时刻 − 指标保留期)。
   - 最大窗口为 `stage_a.card_window_max`，默认 24 小时：区间查询最多约 300 个点，步长 5 分钟；
   - 指标保留期为 `stage_a.metrics_retention`，不填时不限。
3. **锚点留在原处**：卡片的 CEL 里 `window.anchor` 仍是首次触发（或重新锚定的告警）。按锚点比较前后的卡（例如开始前后的 5xx 峰值）在长期事件里锚点可能早于窗口起点，那一侧没有点时无法判定，这与原来"锚点之前没有数据"的语义相同。
4. **指标在窗口前段不存在不是观测盲区**：判定只看窗口里有没有样本，窗口内之后出现的样本照样参与判定。终点就是评估时刻，有数据的卡不会因为窗口前段缺数据而判为 no_data。
5. **同一个窗口规则用于所有执行路径**：阶段 A 的证据卡、阶段 B 的卡片检查与查询模板（`runCardCheck`、`runTemplate`）都用它（与 ADR 0131 一致）。信号与标签档案的探测时刻取各卡窗口终点中最晚的一个，长期事件就是评估时刻（锚点时指标可能还不存在）；在评估时刻找不到可用备选的信号（数据在窗口后段之前就断了，例如回放、重启后补跑），以及在评估时刻探测失败的标签档案，再在锚定窗口的终点探测一次。组件名称的求值时刻不早于终点减去最大窗口。
6. **不变的部分**：`rerun`（按给定终点重跑）与评测、回放的窗口不变；它们传入的 now 就是快照的 as_of，第 1 条同样适用。

实现：

- `packages/packs-sdk/src/runtime/run-card.ts`：`cardWindow` 增加 `extend`；
- `apps/srenautix/src/stage-a/pack-evidence.ts`：`extendTo`、`execute`。

## 结果

集成测试 `stage-a-window.test.ts`，用真实 Prometheus：

- 首次触发在 13 天前、PDB 指标 11 天前才开始：窗口是评估时刻之前的 24 小时；允许驱逐数为 0 的卡判为异常，健康副本卡判为正常，不是观测失明。
- 最大窗口设为 30 天时，窗口起点早于指标出现，卡照样按之后的数据判定，不是观测失明。另设 7 天的保留期时，起点为评估时刻减 7 天。
- 已恢复的长期事件：终点取恢复时刻。
- 8 小时的事件：窗口终点都是评估时刻。按之后升级的告警重新锚定的实体，起点在那条告警之前；其他实体的起点在首次触发之前。

# 0091 领域包来源、pack.lock 与用户层

## 背景

领域包决定研判看什么数据、怎样下结论、提议什么动作，属于需要审计的输入（DESIGN §6.3）。回放与评测要能确认用的是哪一批包；用户需要调整阈值、禁用不适用的卡片，又不能因此分叉上游的包。

## 决定

1. **来源**：内置包随发布；Git 来源必须固定到 40 位 commit，写成 `git+<url>@<commit>`；OCI 来源必须固定到 sha256 digest，写成 `oci://<仓库>@<digest>`，先用 cosign 校验签名（keyless 校验身份与签发方，或密钥对校验公钥），再检查制品类型 `application/vnd.srenautix.pack.v1` 与单层结构，最后用 oras 拉取。签名校验失败时不拉取。
2. **只含数据**：包目录只允许约定的文件，每个文件按契约 schema 校验；出现其他文件时拒绝加载。
3. **pack.lock**：记录每个包的名称、版本、来源与内容哈希（每个文件取 sha256，按路径排序后对"路径与哈希"的列表再取 sha256），以及每个用户层文件的哈希。每次研判和评测都记录 lock 本身的哈希（`sha256(JCS(lock))`）；`srenautix pack lock --check` 与加载结果比对，不一致时失败。
4. **用户层**：层文件（`srenautix.io/pack-layer/v1`）只修改一个包，按声明顺序合并（组织在前、集群在后）；层内按 `extend → params → patch → disable` 执行；`patch` 是相对合并后文档的 JSON Pointer；合并结果重新按契约校验并重新编译。
5. **规则提议**：只能引用动作目录中已有的动作，参数名与类型按目录检查；包里的 `action-requests.yaml` 只是申请，经 Git PR 合入策略后才生效。

## 结果

- 任何一次研判都能由 lock 哈希追溯到确切的包内容与用户层。
- OCI 分发的包需要运行环境里有 `cosign` 与 `oras`；离线环境用 Git 来源或预先拉取后作为本地目录加载。
- 用户层让阈值与禁用项留在用户自己的 Git 仓库里，上游包升级时直接合并。

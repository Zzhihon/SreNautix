# 0206 地图回放的变更轨道

状态：已采纳

## 背景

地图回放（ADR 0205）只画事件：每格还在触发的事件数，与这一格里新触发的事件。复盘要回答的第一个问题是"出事之前改了什么"，回放上看不到变更，要到每个事件的详情里一个个找。

变更已经有统一的来源。事件引擎关联变更时调用 `engineChanges`（`roles/server.ts`），合并五类变更：

- 变更源写入的 `server.change_events`，例如 GitHub 和 SQL 审计；
- 从拓扑事件推导的发布（ADR 0104）；
- kube-state-metrics 兜底的发布；
- 退役；
- 已合并、尚未同步的提交（ADR 0161）。

每个变更带种类（`rollout`、`gitops_sync`、`config`、`scale`、`cordon`……）与触及的组件键。

## 决定

### 1. 时间轴接口带上变更（契约 2.67.0）

- `GET /v1/topology/map/timeline` 增加 `changes` 与 `changes_status`。
  - 变更取自 `engineChanges`，与事件详情里的相关变更是同一个定义。
  - 只返回调用方读取作用域内至少一个目标的变更。
- 每个变更的 `components` 是目标放到现在的地图上的位置，用的是事件落点的同一个函数（`mapPlacer`）：
  - 组件的键；
  - cordon 的目标是节点，落在节点条上。
  - 目标不在地图上时为空，例如 Argo CD Application。
- 最多 2000 个，超出时 `changes_status` 为 `truncated`，只留最近的。读取失败时为 `unavailable`：事件照常返回，时间轴说明没有变更行。
- 同一（集群、区间）的变更缓存 60 秒。控制台每分钟取一次时间轴，24 小时的发布推导要扫当天的拓扑事件。

### 2. 时间轴上的变更行

- 直方图下方加一行，每格按分组叠放：发布（rollout、ci_deploy、gitops_sync、operator）蓝，配置（config、runtime_config）紫，容量（scale、cordon）灰，其他（retire、other）粉。新触发的事件在直方图上方，变更在下方，先变更、后出事的时刻在同一列对得上。
- 选中的一格在时间轴下方列出它的变更：时间、种类、摘要、版本与链接。
  - 摘要来自变更源，是不可信文本，只作为文本显示。
  - 链接只接受 http(s)，在新窗口打开。

### 3. 地图上的变更标记

- 所看时刻之前 1 小时内（`CHANGE_WINDOW_MS`）的变更，在它触及的组件与节点上标出 "◆ 变更数"。合并的组取全部成员的变更。
- 变更早于落在这个组件上的某个事件的首次触发时，标记换成状态红色：先变更、后出事件。
- 这只是时间上的先后，不是关联分级；分级仍由事件引擎计算（ADR 0169），在事件详情里给出。
- 组件侧栏列出这些变更。

## 考虑过的方案

- **服务端只读 `server.change_events`**：拓扑推导的发布不在这张表里，CCHP 的发布大多是这一类，回放会漏掉最常见的变更。
- **每一刻的地图接口带变更**：播放时每格多一次变更推导。时间轴取一次，控制台按所看时刻筛出前 1 小时。
- **按变更与事件的关联分级标出嫌疑**：分级需要事件的成员告警与变更的依据，只在事件引擎里有。地图标出时间先后，详情页给出分级。
- **变更放到当时的地图上**：组件键在不同时刻基本不变，按现在的地图放置，少一次时间点查询。当时存在、现在已删除的组件上的变更不画在地图上，仍在时间轴的列表里。

## 结果

- 单元测试：变更按格、按分组计数；所看时刻之前 1 小时的筛选与"先变更、后出事件"；地图与节点条的标记；侧栏与时间轴列表；不可信摘要只作文本；非 http(s) 链接不渲染。
- 参考部署（CCHP）2026-11-14 最近 24 小时的 29 个事件都没有关联到变更，所以无法用事件详情做真实数据预览。布局用线上地图加构造的变更检查过，截图没有放进仓库。
- 部署后要测量两项：24 小时区间的变更数量，以及时间轴接口的耗时。

# 0043 状态库不可用时的阶段 A 降级通道

## 背景

DESIGN §7.1 与 §15.1 要求 PG 不可用时 server 在内存中继续归并、直接调用渠道发送，消息带"状态库降级"横幅，PG 恢复后补写，并从 Alertmanager 与 `ALERTS` 重建活动告警。

## 决定

1. 每轮成功的事件对账之后，降级通道保存一份起点：当时的告警、拓扑节点与边、拓扑版本、全部未合并的事件。
2. 接入层写库遇到连接类错误时，把告警留在内存（等待补写），并交给降级通道：告警只按告警目录分类，组件取命名空间伪组件（实体解析需要拓扑查询）。
3. 降级通道用 packages/core 的同一套收敛、根因排序与对账在内存中重算事件；版本变化的事件执行证据卡（数据源查询不依赖 PG），生成 `degraded=true` 的阶段 A 报告，经通知层直接发送，不带回调按钮。
4. PG 恢复后：接入层补写内存中的告警，事件流水线照常重算；通知层把降级期间发出的消息写回发送队列，后续编辑同一条消息；60 秒对账从告警源补齐期间遗漏的告警。

## 结果

- PG 故障期间新的告警仍在 60 秒级别内产生消息，且与恢复后的消息是同一条。
- 降级期间不签发审批、不入阶段 B 队列；这两类状态都必须持久化。

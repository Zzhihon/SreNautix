# 0085 导入旧版 Ops-Agent 的回放种子

## 背景

参考集群在迁移前由旧版 Ops-Agent 研判，导出器把旧事件的查询邻域写成自描述的 zstd JSON Lines（格式名 `cchp-srenautix-seed`，版本 1，目录内附 FORMAT.md）。种子含参考集群的事实，只保存在部署方本地，不进入本仓库。需要把它转换为评测用例与快照，作为 P0 的回放用例集。

## 决定

1. 导入器 `srenautix eval import-seed --dir <种子目录> --cases <用例目录> --suite <名> --cluster-id <id>` 逐行读取 `units`、`calls`、`logs`、`raw`、`snapshots` 五类文件与 `catalog.json`，第一行必须是该格式版本 1 的文件头。
2. **组件**：旧版组件 id 映射为组件键 `legacy.component:<id>`（旧版没有 Kubernetes 对象级的组件）；依赖边来自 `catalog.json` 的静态拓扑，节点来自单元的两跳邻域。
3. **事件与证据**：单元的事件转换为契约 `Incident`（根因为唯一候选，告警为成员，变更为 `ChangeEvent`）；卡片（事件自身与邻域的证据链、自动检查）转换为阶段 A 的证据卡结果，异常卡的异常起始时间取所在告警的 activeAt，邻域组件范围的卡没有告警，为 null。
4. **查询快照**：VictoriaMetrics 区间与瞬时查询、Loki 日志行、Tempo 搜索转换为查询快照条目；告警状态与单条 trace 没有对应的集成能力，不导入。与单元日志窗口重叠的日志块按日志组合并为一条日志查询（只取窗口内的行，每组最多 5000 行）；单元用到的原始序列（5 分钟 rollup 的平均值）合并为一条区间查询，带"降采样"警告。
5. **标准答案**：优先取知识条目（事故复盘）的根因（来源 knowledge），其次取快照行的 ground_truth（来源 imported）；都没有时用例进入 `<suite>-unlabeled`，即"稍后标注"队列，不计分。没有根组件的单元（以知识条目时间窗为单元、没有告警）跳过并在汇总中列出。
6. **防泄漏**：知识条目都作为可检索材料带 `learned_from`（条目 id 与所选事件键）；每个用例的 `learned_from_keys` 含自己的事件键与知识条目 id，回放时这些材料被排除；参考案例只取用例开始之前已解决的复盘。
7. 用例 id 为 `legacy:<单元名>`，事件、快照与报告的 id 由单元名确定性生成（同一份种子重复导入得到相同的 id）。

## 结果

- 导入器用一份按该格式写出的合成种子目录测试（两个事件单元、一个知识条目单元、日志块、原始序列、快照行），覆盖映射、窗口裁剪、跳过规则与防泄漏。
- 处置判断在旧版种子中没有标准答案，这些用例只评根因；处置准确率需要在控制台补充标注后计入。

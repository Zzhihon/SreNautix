# 0123 conclude 只负责选择，档位由结论阶梯决定；处置判断的 ignore 条件

## 背景

conclude 的提示词原先写"证据不足时 hypothesis_id 为 null"，系统提示词又列出 `evidence_consistent` 的四个条件。CCHP 重建评测的研判记录显示，大模型路由把这四个条件当成选择的前提：账本中有处于支持状态、并且就是正确根因的假设时，它仍以"竞争假设没有检验""没有区分性检查结果""无法满足唯一根因判定条件"为理由返回 null。证据是否充分本来由结论阶梯按代码判定，模型的弃权把本应为 likely 的结论降为 inconclusive。

处置判断方面，良性用例（正常的业务负载高峰、外部上游服务方的偶发慢请求）与根因在集群外部上游的用例，研判一次也没有给出 ignore，提示词对 ignore 的说明只有"只有预测类或长期告警、证据显示正常"。

## 决定

1. **选择与评级分开**：conclude 的任务说明写明结论档位由代码按证据计算；竞争假设没有检验、没有区分性检查结果、缺少某类数据都由档位体现，不是放弃选择的理由。账本中有处于支持状态的假设时，模型选出其中最能解释全部成员告警与证据的一个，仍缺的证据写进 investigation 类的修复建议；只有账本中没有任何处于支持状态的假设时才返回 null。
2. **选择的优先顺序**：机制能解释全部成员告警的、变更或异常先于症状的、处于依赖链更深处的组件优先；在本次症状之前很久就一直触发的告警通常是背景状况，它所在的组件不因此成为根因。
3. **ignore 的条件**：除预测类或长期告警、证据显示正常之外，增加两类：根因在集群外部的上游服务方、集群内没有可处置的对象；告警反映的是正常的负载变化，资源没有到瓶颈。act 包含需要修改仓库配置的修复。
4. **代码约束不变**：观测失明时处置一律为 escalate；act 没有有效提议时按严重度改写；选中的假设必须未被推翻；模型仍然弃权时按 ADR 0120 由代码代选。

## 结果

- 修改 `apps/srenautix/src/prompts/{zh,en}.ts` 的 hypothesize 与 conclude 任务说明，提示词哈希随之变化，研判清单记录新的哈希。
- 评测对比 top-1、选择性准确率、良性用例误报、处置准确率与 pass^k，任何一项回退都不合入。

# 0120 模型在 conclude 弃权时由代码按账本选中结论

## 背景

DESIGN §7.3：假设账本、停止规则与结论阶梯都由代码维护，模型只提出假设、检查与结论文字。conclude 的输出里 `hypothesis_id` 可以为 null，表示模型认为证据不足；之后结论阶梯对没有选中假设的结论一律给出 `inconclusive`。

CCHP 有标注用例的重建评测（17 个用例 × 2 条路由 × 3 次）中，大模型路由 45 次有根因标注的运行只有 2 次给出 likely。其中 18 次是同一种情况：账本里排名第一、处于支持状态的假设就是标注根因，根因上有阶段 A 的异常卡，模型却返回 `hypothesis_id: null`，理由通常是竞争假设没有检验或没有区分性检查的结果。这些条件本来由结论阶梯的四个条件衡量，模型按它们自行弃权，等于把阶梯的判定重复了一遍，并把本应是 likely 的结论降为 inconclusive。

## 决定

1. **代码代选的条件**：conclude 返回 `hypothesis_id: null` 时，账本中恰好一个假设处于支持状态，并且这个假设有范围内的异常卡（`supportCards` 非空），代码选中它作为结论。两个及以上假设处于支持状态时（打平）不代选；只因人工反馈固定为支持、没有异常卡的假设不代选；模型选了不存在或已被推翻的假设时仍然改为无法判定，不代选。
2. **档位上限**：代码代选的结论按结论阶梯照常计算四个一致性条件，档位最高为 `likely`；四个条件都满足时也是 `likely`，`consistency` 字段如实记录四个条件。模型的弃权保留为降一档的依据。
3. **留痕**：`validation_notes` 写明"模型弃权，代码按账本选中 <假设>（<根因>）"、支持卡引用与模型给出的弃权原因；四个条件都满足而档位为 likely 时另写一条说明。
4. **其余不变**：处置判断、修复建议与提议仍取自模型的 conclude 输出，按原有规则校验；`undetermined_reason` 在代选后置空。结论输出的契约不变。

## 结果

- 实现在 `apps/srenautix/src/research/validate.ts`（`ledgerPick`、`Validated.chosenBy`）与 `ladder.ts`（`judgeLadder` 的 `chosenBy` 参数）；单元测试覆盖代选、打平不代选、只有人工固定支持不代选、模型选了被推翻的假设不代选、档位上限。
- 代选的结论是 likely，满足自愈 PR 的触发条件（likely 及以上）；PR 仍受每小时上限与四类修复的约束，并且由人审阅合并。
- 评测同时比较 top-1、选择性准确率、良性用例误报与 pass^k，任何一项回退都不合入。
